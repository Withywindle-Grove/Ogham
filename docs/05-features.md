# 05 — Features (R1 behavior)

How each R1 feature works. Screens are in `06-screens-and-design.md`.

## Sign-in

- R1 sign-in is by email **6-digit code** only (no passwords, no Google). A code works inside the installed app on iPhone/iPad, where email links open in the browser instead. Devices stay signed in until the user signs out. No tablet lock.
- After sign-in, a **campaign picker** lists every campaign with the user's role and active character (and its company; a player's row shows that character's portrait, or the campaign's sigil letter if there's none), "Start a new campaign (as GM)", and a **Have an invite code?** box. An invite link (`/join/CODE`) or a typed code opens a preview (campaign name and GM) with **Join**; Join leads to character creation (see Joining). Signing in first keeps the link's code.

## Campaigns

- A user can be in several campaigns (GM in some, player in others). Each campaign's data is fully separate.
- **Rules library** (account ⋯ menu, for everyone: a library is your own): your library of imported packs; import (JSON or Markdown, with a preview), update from a newer file (with a preview of changes; each campaign using the pack gets a log line "Setting rules updated: <pack> <old> → <new> (N changed, M removed)", and tapping it lists them, with GM-only entries named only to the GM), and see what's in each. **Rebuilt 2026-11-02** (`design/rulings/m5b-0d-library-and-campaign-rules-2026-11-02.md`, lr-1 … lr-3; mockup `design/mockups/library/01-rules-library.html`): grouped by kind (Setting rules · Adventures · Homebrew) with filter chips, sort by name (default) or last updated, a find field from 8 packs; each pack in four lines — name · its own description and what it needs · what it holds (counts in the pack's words; every kind it holds is counted, a rules set last, "1 rules set", and "Nothing in it yet" only when it holds nothing: lr-2a, 2026-11-13) · who uses it, version, date; Browse and Update on the row, Edit pack (homebrew), Export and Delete under ⋯ ("About this file" moved behind Browse › About). **Convert a book with an AI…** shows the instructions to paste into an AI chat with your own book, with a copy button. Campaign → Setting rules attaches them (their optional rules open first, all choosable, even those locked later), imports straight in, and sets optional rules. Each optional rule's name has an ⓘ: tapping it shows whether the rule can change later and the pack's notes on it. Only "Locked" shows without asking. In a running campaign, changing a rule that warns (one choice, or "Use all defaults") first asks "Changing this mid-campaign can affect characters and records made under the old rule" with **Change it** and **Keep**, once per rule while the optional rules are open.
- **Stacking** (M3): the campaign's setting rules sit in one order, top first; when two have the same entry (same kind and id), the higher one wins. ↑ ↓ on each move it (logged; Undo puts the order back). **Homebrew is one layer (ruled 2026-10-24):** every homebrew pack, the campaign's own and imported ones, sits above all setting and adventure packs; the order inside each layer is freely draggable, and newly added packs go on top of their layer. Exceptions are per entry, from the browser: on an entry that's in more than one, the GM can read the other versions ("See the River Rules version") and pick one with **Use this version**, or go **Back to the stack order** (both logged). Players see only the winning versions. Optional rules are each pack's own and never compete.
- **The in-app editor** (M3, GM): Campaign → Setting rules → **+ New homebrew entry** (pick the kind, fill in a simple form, Save), and in the browser **Edit as homebrew** on an entry from other setting rules (a homebrew version that wins: saved into the campaign's own homebrew, ruled 2026-10-25, replacing "or another homebrew pack the GM picks"; it asks once if a higher homebrew already has the entry, "Put yours on top?", or the entry has a per-entry exception, "Use your edit instead?"; the sheet then says "Your version (<pack>)", ruled 2026-10-24) or **Edit** / **Delete from homebrew…** on the campaign's own. Problems show in plain words before anything is saved. Logged; Undo works on changes. Not offered in a retired campaign. (7a: items, stat blocks, conditions, light types, XP tables; 7b: classes, races, spells, spell lists, starting kits; 7c: tables, treasure types, rules sets, optional rules, hooks as text, sheet layouts — every kind.) A homebrew optional rule appears under the homebrew's **Optional rules** like any other; the browser lists the campaign's own homebrew optional rules (for the GM) so they can be edited, and never offers "Edit as homebrew" on another pack's optional rule (optional rules never compete). Linked entries are picked from a list or typed by name ("Glimmer, Mire light"); a name that isn't in the campaign's setting rules is caught before saving. Parts a form doesn't show yet (a class's progression, armour and weapon rules) are kept untouched and the form says so.
- **The campaign's own homebrew** (M3; ruled 2026-10-24): made the first time something is saved into it (the in-app editor, and later one-off items, custom tables and foes), named "<campaign> homebrew". It's only special in being created automatically: otherwise it's listed, ordered, exported and removed like any homebrew pack (removing one that has entries asks first). One per campaign, made only by its GM. Each homebrew pack's ⋯ has **Export as pack file** (a homebrew pack file with its `meta.id`; no campaign state). Tapping an entry in a homebrew's **What's in it** opens it to edit. **Ruled 2026-10-25:** inside a campaign, an edit always saves into that campaign's homebrew (moved to the top when the GM agrees); imported homebrew packs are edited only from the Rules library (**Edit pack**), which shows "Used by N campaigns" before saving. A campaign's homebrew stays with its campaign: its ⋯ has **Copy to Rules library**, which makes an independent homebrew pack, "<campaign> homebrew (copy)"; later edits to either don't affect the other. Export as pack file stays; both are behind ⋯.
- **Browsing setting rules** (read only, M3): **Browse these rules** in Campaign → Setting rules (everything in the campaign's packs), **Browse** on each pack in the Rules library, and for players ⋯ → **Setting rules** on the Player screen (and a Setting rules button on Your characters, so it's there before a character exists). One folded group per kind ("Classes · 22"), a search by name, and each entry's details in plain words: known fields with plain labels, ids shown as the names they point to, anything else as "Label: value", and formulas worked out: an entry with formulas has an **At level − 3 +** picker (a player starts at their active character's level, the GM at 1) and each formula shows its value beside it ("2 + level turns → 5 turns"; fractions rounded down and marked). On a landscape tablet the details sit beside the list. Optional rules aren't listed (they're set on the Campaign screen). Players see only the player-facing kinds (the database sends nothing else); from M4b, items only if for sale or known to the party (Inventory, "What players' devices get"), and item fields a pack marks `gmOnly` aren't shown to them. When the entries come from more than one pack, each says "From …", and an entry in several shows once: the winning version, with "Also in …".
- **Rules rows, test feedback 2026-11-03** (`design/rulings/m5b-test-feedback-2026-11-03.md`): no Show all, a pack section folds and opens to every rule (tf-5); rows keep their place while you work and re-sort on reopening (tf-2); a shared rule (ruleKey group) lists every pack's choices under pack names, one tap picks (tf-1); the creation rules step opens with the App section (tf-7).

- A campaign has its own **name and sigil**; the GM changes them (no vote). Tapping the name or the sigil opens **Edit the campaign**: rename it, change the sigil or remove it (the campaign's first letter shows instead).
- A campaign has **zero, one or many companies**. Each company has its own charter, treasury, titles and votes. A character belongs to **at most one** company at a time, and may belong to none (e.g. a newcomer before joining).
- **A pack that needs another not attached** (rq-1, `design/rulings/dec-required-packs-and-pack-choices-2026-11-13.md`; GM only): on Setting rules, the row of each attached pack whose `meta.requires` names a pack not attached to the campaign carries a Warning line, "<Pack> needs <Other>, which isn't attached to this campaign." It refuses and hides nothing: the line stays until the needed pack is attached or the needing pack removed. A retired campaign keeps the line without the button (nothing in it can change). A company can be deleted only while no character is in it (archive-only once charters and treasuries exist). Players see their character's company on the picker row and on their character card.
- **Rules for this campaign** (B15, ruled 2026-10-25; one part, ruled 2026-10-26): one screen, first in the GM's Rules tab, with the app's settings in fixed topic groups (Characters · Adventuring · Combat · Items and treasure · Time and calendar · Table and players) and the packs' optional rules as **one folded group per source** after the topic groups (ruled 2026-11-02, lr-7; before: one Optional rules group by category), each group with its count line ("23 rules · 2 changed"), the rows as in set-up step 3 (what it does, source and page, when it can change), editable in place with Undo; "Reset to the books' defaults" replaces "Use all defaults". **Copy the set-up** sits at the foot (cs-set-1, ruled 2026-11-10, `design/rulings/m5b-rewalk-campaign-setup-2026-11-10.md`): one tap puts a plain-text summary on the clipboard with the toast "Set-up copied": the campaign's name; each pack with its version, top of the stack first; the start level; the app's settings (with the start time and calendar start); then every optional rule on offer as "<rule>: <choice>" in the pack's words, those changed from the book first (with the pack's short name after the rule when more than one pack has optional rules, and "(decided above: <pack>, <choice>)" on a rule another pack decides); a pack without a version shows its name only.   - **A pack's player content** (pc-1, ruled 2026-11-05, `design/rulings/packs-player-content-switch-2026-11-05.md`; built after the M5b gate): each loaded pack that adds classes or kindreds has one row at the top of its group, and in campaign set-up, **Offer this pack's classes and kindreds to players**, On by default. ## Campaign (GM)

- One GM screen, **Campaign**, replaces the GM part of Settings. Its sections follow the GM's tabs (06, Navigation): **Players** (players and characters: invite by link or code, approve new characters at the level the player chose, see who plays whom; players only, as NPCs and monsters live with the GM console; then Companies and **Inventory**: the Party stash first, then "Whose pack"; renamed from "Party stash" 2026-10-24) · **Rules** (setting rules: attach, import, update with a preview, optional rules). Still to come, with their features: **Handouts and maps** · **During play** · **Data**. The log opens from the top row.
- Device preferences (theme, text size, "Dim pictures in dark mode" (default On), ability captions; the darkness effect switch went with the dim at the M5 gate, R3 audit 8) live in a personal menu everyone has (⋯ → This device). The theme starts from the device's own light/dark setting. Text size: Standard · Large · Larger (about 100 / 112 / 125%), per device, starting from the device's own text size.
- **Handouts and maps (R1):** upload images or PDFs; each is visible to the GM only, everyone, or chosen players; **Reveal** shares it. Revealed items appear in a Handouts list on Scene. No fog, tokens or drawing (later release).
  - **Direct uploads** (ruled 2026-10-24) go into app storage, GM only until revealed, under the same access rules and per-kind visibility tests as revealed copies. Images are resized on upload to WebP, up to 2400 px on the long edge; PDFs are capped at 10 MB. Adventure-pack images stay in the GM's Google Drive (see Adventures).
  - Handouts shows two groups: **From your adventure** and **Your uploads**.

## Modes

- The GM switches the whole campaign between **Adventure** and **Downtime**. Everyone's screens follow.
- Players can always open their own full sheet; mode changes what's front and center, not what's allowed.
- **Start downtime** (M5b; ruled 2026-10-30, settlement dry run, ST10; split from End expedition by dt-2, built in step 6a: the strip's ⋯ in town, refused while an expedition is under way) applies a full rest automatically to every character in play (no Full rest button), and switches to Downtime; secret check results reach players then; the town screen stays for buying and selling (Settlements, below), and time moves with +1 day, +1 week or a date until the downtime design session (08). **End downtime** (ST11) returns to Adventure; more comes from the downtime design session.

## Characters

- Universal core: name, portrait (upload), level, HP, XP, status, notes. Everything else comes from GM-defined fields or a sheet layout in a pack.
- **Sheet layouts from setting rules:** after adding setting rules that have a sheet layout (and from **Sheet layout…** on their row, and on the last step of starting a campaign), the GM sees its fields and can **Use this sheet layout**; fields the campaign already has stay as the GM made them; logged.
- **GM-defined fields** (Campaign → Rules → Rules for this campaign → **Character fields**, a collapsible group shown only when the rules name fields: the campaign has fields, the homebrew's "Edit character fields" opens it, or there are no setting rules yet; ruled 2026-10-28, N20): the GM adds fields (Number, Text, Long text, Yes/No, List), puts them in categories (shown as headings, e.g. "Abilities"; picked from the categories in use or **New category…**, ruled 2026-10-26) and orders them (a tap on a field's row opens it, as Edit does), and marks which show on the character card. All fields are optional. Hiding a field keeps its values; a field nobody has filled in can be deleted. In "Who are they?" the portrait comes first, under the name, then level, HP, backstory and the GM's fields.
- Race is optional and comes from a pack (it fills vision and notes). Without a pack, race and class are ordinary GM-defined fields (text or list); attaching a pack later means re-picking them from its lists. Characters store a list of classes; R1 screens show one. Multi-class screens are R2.
- In R1 all class skills show their number (GM-rolled skills are R2).
- **At hand** (ruled 2026-10-23; a weapon line's figure opens its breakdown like every other figure, with "Open <item> ›" at its foot, sq-4, 2026-11-04): fills itself with what's in hand (weapon, shield, a lit light) and any worn or held item that has uses or charges; worn armour and clothing stay on the Pack tab only. Pins add extras carried elsewhere (a potion in the backpack, a stowed wand), notes, and later spells: the Pin star in the head of the item's sheet ("Pin to top", filled once pinned; plan m5b-players-screens-standard C, 2026-11-07, replacing the quiet "Pin to At hand" button), with no limit; a pinned item's line on the Pack starts with the small filled star. Both show together, each once (a pinned item already in hand shows once). Every entry can be removed by its player: a pinned one with the star ("Unpin"), one that fills itself with "Hide from At hand" (on the item's sheet and on the entry), which stays hidden until "Show in At hand" on the item's sheet. Pins and hiding go away by themselves when the item leaves the character. Pins are logged; hiding and showing in the detailed log only. Each entry opens its rules reference on tap. Nothing shows when there's nothing in hand and nothing pinned. **Only what has an action is At hand, and every row carries it** (Francis, 2026-11-07, on #552): Use a charge; a light's Light or Put out; use one up, named by the item's kind (Fire for ammunition, Drink for a draught, Eat for food, Use for another stack), logged as what happened ("Wren drank a Moss draught, 1 left"), with Undo in the toast and the last one leaving play (the log keeps a copy); Attack for a weapon with nothing to count (until M6 it opens the weapon's sheet). **On the Player tab** (tfh-1 to tfh-5, 2026-11-19, `design/rulings/dec-test-feedback-weapon-quiver-2026-11-19.md`; page M2, approved 2026-11-19; built for this tab) a weapon's name and its Attack open the same short pop-up: the two rolls and its qualities, then Give to…, Put in…, Hide from At hand and Drop, with no slot, hands, value or weight; the other things At hand open the same short shape (what it does now, then the quick buttons); a weapon in hand always shows the Pin star, and pinned while in hand it stays At hand when put away. Attack is repurposed when fights are built. **The Quiver lists only the kinds the character carries** (tfh-6), and says so in one line when none is. A pinned or worn thing with nothing to do stays in its own group on the Pack. From the M5 gate (⚑ C3, ruled 2026-11-01) a weapon at hand shows its **attack bonus and damage** now, worked out from the pack's item data and the character's level and scores (the numbers M6's fight panel will use); a pack with no formula shows the damage die alone. The damage adds the modifier of the score the rules set's `attack.damageScore` names (ruled 2026-11-01, 07): "+1 · 1d8+1"; without the field, the die alone. **The Attack sheet** (as-1 … as-3, 2026-11-10, `design/rulings/m5b-attack-sheet-clarity-2026-11-10.md`, layout B; reorders ah-1) opens with **the two rolls**, to hit then damage, each a card with its die's glyph and one plain line carrying the sum ("Roll 1d20 + 1 to hit", "Roll 1d6 − 1 for damage"; a zero is dropped from the line, "Roll 1d20 to hit"), and under it **the parts as rows**, each with its own figure, never a running total (the class at its level, each score by its name and value, the mode's to-hit, the weapon's die, the rules' change to it, a score that doesn't add said in words). ## XP and levels

- Each character has a running XP total and "XP to next level" from thresholds (entered by the player or from a class pack).
- **XP waiting** (M7-1, ruled 2026-10-28): XP collects in one **XP waiting** pot on the GM console, fed by fights (End fight, M6-11), foes the party got past (the encounter endings), **Treasure** lines from Split Loot (M7b; only when treasure gives XP, see Purses) and bonus XP. Each line can be edited or removed. **No forced moment:** End expedition, End session (built in M5) and the GM console each show one quiet line ("445 XP waiting · Award now"; ruled 2026-10-29, E37); the GM can award at any time. XP is usually given at session end, but GMs vary.
- **Award XP sheet** (GM):
  - The waiting lines, then **+ Bonus XP…** with a reason (for one character or the party; bonuses sit on top of the split).
  - **Who shares**, as chips: by default the characters who went on the expedition (the snapshot taken at Start expedition: the approved, active characters then; ruled 2026-10-29, E36); chips change it; dead characters are left out until tapped back in. Benched characters earn no party XP. **Retainers** join Who shares with hirelings in M9, taking the pack's `xp.retainerShare` (a fraction such as 0.5); until then the GM can give them Bonus XP (E35).
  - The **shares**. **Pack bonuses** are added per character, each named with its source: the prime requisite bonus is read directly (the class's `primeXp` and the rules set's `primeRequisiteXp`); any other bonus a pack defines is a factor hook on the target `xpAward` (E38). Tapping a share shows the sum ("127 + 10% prime = 140"), the shared "where this number comes from" pattern. The total under the button explains itself ("445 waiting + 19 from bonuses").
  - **Rounding:** shares round to the nearest whole number, and half shares round up, unless the pack says otherwise.
  - **One-level cap:** when the pack limits gains to one level per session, **Cap** / **Keep** appears only on a character the award would push past it ("Over the one-level cap by 1,100"). Nothing is cut automatically.
  - With nothing waiting: "Nothing waiting" plus **+ Bonus XP…**.
  - The single accent button **Award N XP** logs one undoable step. Players get a quiet "+N XP" toast, and "▲ Ready to level" where it applies.
- **Level up** (M7-2, ruled 2026-10-28): reaching a threshold shows a quiet **▲ Ready to level** badge (on the Urgent strip); the badge is the only reminder, never a nag. When the class comes from a pack that has progression data, the app fills the new hit dice, attack values, saves, spell slots and skills and shows them as a preview; the player confirms or edits. A player can switch their character to manual level-up ("I'll enter it myself") and enter everything themselves. Without pack data the player enters the changes. Either way it's logged. HP rolls stay physical: the player rolls and types the result.
  - **The preview** (approved R1 design): HP roll tiles, What changes, Use / Keep for edited values. When the setting's new value differs from a value the player edited by hand, it asks: "You set Breath to 13 · your setting says 14 · **Use 14** / **Keep 13**". Values the player never edited update automatically after the preview.
  - **Additions:** new abilities show **Rules ›** (one tap to the rule); **Learn a spell · Choose ›** when the class's `spellcasting.learnByLevel` gives new spells at that level (the same picker as creation; without `learnByLevel` there's no Learn a spell step; ruled 2026-10-29, E43); **HP without a roll** when the progression row's `hpGain` gives a fixed gain (`{ fixed, addCon }`; never guessed from text; E44): the tiles are hidden and the reason is stated. HP roll tiles go up to d10; d12 and bigger use the shared number stepper (typing allowed). Confirming before the roll stays tappable and says "Tap your roll first". **Several levels pending** run as one preview after another.
  - **When a character can level:** a pack setting with a campaign override, **Downtime only** (default) or **Any time**. "▲ Ready to level" always shows. In a Downtime-only campaign, tapping it during an adventure offers **Ask the GM**: the request lands in the GM's **Waiting for you** list (the GM inbox from M8); **Allow now** opens the preview for the player, and **Not yet** says so quietly. Both are logged.
- **Lose a level** (R2, moved from M7 on 2026-10-28; GM): reverses a level-up using the pack's data and its `levelLoss` rule, with the same Use/Keep choice for values the player edited; logged and undoable.

## Purses and party fund

- Each character has a personal purse; amount hidden from other players, visible to the GM.
- Party fund is shared and visible to all.
- Multiple denominations by value are supported per campaign; coin weight counts coins as one denomination.
- Any member can add, edit or roll back party ledger entries; everything is logged.
- **Money in M7b** (M7b-1, ruled 2026-10-28): the R1 boards (Split Loot, Treasury, Charter) stand, with the changes below. Unchanged: the fund percentage and its exceptions, the remainder to the fund, equal shares with companies off, recurring Due, GM-approved places, stored amounts private.
- **Before M8** (no titles or votes yet): Split Loot and the Treasury are run by the GM; any player can open Split Loot and **send it to the GM as a draft**, which lands in the GM's Waiting for you list. M8 switches on the Treasurer title (Split Loot and Treasury as in 03) with no rework, because commands already record who proposed what.
- **Split Loot** (the GM until M8, then the Treasurer or GM): enter the haul → apply the charter's share distribution → preview each share and each carrier's new load → adjust → confirm. Creates party-fund and purse entries in one step.
  - **"What did you bring back?"** fills itself from the coins and gems in the Party stash and the coins and gems claimed this expedition, which the split **takes out of the characters' packs** into the haul (ruled 2026-10-29, E45: no double counting); each line has **Keep out of the split**, every line is editable, and **+ Add a valuable** stays. Taking them out, splitting and paying out are one undoable step.
  - **One confirm** (it changes every purse), then it's **one undoable log step**: whoever ran it, or the GM, can undo it if nothing changed since.
  - **Treasure XP:** only when the setting gives XP for treasure (the pack's default; the campaign option **Treasure gives XP** overrides it), the split adds a "Treasure · N" line to the XP waiting pot (see XP and levels). Otherwise there's no Treasure XP step.
- **Purse sheet** (M7b): tapping the coin line on the Player screen opens your purse: each denomination; carried versus each stored place, with **Move** (free in downtime; on an adventure it needs the GM's OK); your **Due** list; and recent entries. It reuses the Treasury's rows. Other players never see it.
- **Split Loot with companies:**
  - **No company** (or companies switched off for the campaign): the haul splits equally among the characters present; no party fund.
  - **Several companies:** the GM sets how much of the haul each company gets; each company's charter then applies to its part.

## Treasury

- The Treasurer manages the party treasure after Split Loot on the Treasury screen (see `03-roles-permissions.md`); until M8 switches on titles, the GM does (M7b-1).
- **Spend** can repeat: just once, every day, every adventure, every week of downtime, every month, or every session (e.g. lodging, hireling wages). Recurring expenses show under **Due**, ready to pay in one tap; paying schedules the next one.

- **What players' devices get (M4b, built with unidentified items; ruled 2026-10-25, discovery first):** a setting-rules item reaches a player's device only if it's for sale or the party knows it. For an unidentified item, only what was learned is known (appearsAs, noticed, revealed facts), and a fact revealed once stays revealed, but for Undo (k22-6). An unidentified item reaches a player as its face (K22a, 2026-11-22): its line, the campaign's library and the log carry its face's name and words, never its true name or a fact not told (04, InventoryLine). Everything else stays GM-side, enforced by the database, with a visibility test run as a player. The GM brings a hidden item into play by handing it out, stocking it in a shop, or setting "For sale in shops: Yes" in homebrew.
- **One-off items (ruled 2026-10-24):** a player's one-off waits for the GM, under the campaign setting **One-off items need approval: On / Off** (default On). It doesn't appear in the pack: the player sees "Sent to the GM for approval", and "N items waiting for the GM" at the bottom of their Pack (tap to see or cancel); waiting items don't count toward the load. The GM approves in one tap from **Waiting for you**, or edits it first, with an **Also add to campaign homebrew** checkbox; declined, the player is told. Both are logged; a decline can be undone from the log, and the one-off waits again (ruled 2026-10-25). An approved character's one-offs wait as before; a one-off the player moves off the unapproved character waits again where it lands. The player's Undo of that move, or of a drop from that character, puts it back waiting for the GM if the character has been approved since (approved if it still waits, or if one-offs need no approval); the GM's Undo puts it back approved (ruled 2026-11-21).
- **Take from a Down or dead character** (ruled 2026-10-29; the named exception to hidden purses, 03): while a character is Down or dead, its pack **and purse** open to the other players like the Party stash: **Take from <name>**, per item or amount, every take logged and undoable. The database enforces it by the character's state. **It ends when Down clears** (ruled 2026-10-29): when HP goes above the setting's threshold (07, `death.at`), or when a Helped wake-up timer ends; being Helped alone doesn't end it while a wake-up timer runs. - **The loot picker** (M6; ruled 2026-10-29): when a search finds nothing, it offers **Add "<typed>" as a one-off**, the same path as Add item's one-offs; the GM's one-offs need no approval.
- **Equip:** armour, shield and weapon in hand as switches; AC, damage and move recalculate live.

## Exploration modes (ruled 2026-10-25: M5 the engine and dungeon play, M5b wilderness play)

- **Modes come from the setting rules** (07, Exploration). The app has no rules of its own: with no attached pack defining modes it offers two plain fallbacks, **Dungeon** (turn by turn) and **Wilderness** (day by day), with the clock, lights and reminders but no checks. When two attached packs both define modes, the GM picks one pack's modes as an optional-rules group (all or nothing). Switching mode is one tap on the time strip, and logged. Packs may add more modes (a town visit, a river journey). **`expedition.mode`** (S17-1) is the current mode's id, read by hooks; it replaces `expedition.setting`, whose old values keep working (`"dungeon"` means the first turn-by-turn mode, `"wilderness"` the first day-by-day mode).
- **Procedure:** **Next turn** / **Next day** is one tap. The order is **each pack's own** (ruled 2026-10-30, DG4; classic-advanced checks first, fae-woodland decides actions first), and a check prompts at its own step. Only steps that need input then prompt, in order; steps the app does itself (lights burning, the clock) run quietly and show in the log; any prompt can be skipped (logged). Note steps show as one quiet line under the time strip (a campaign switch hides them). The whole procedure is one tap away from a checklist button in the top row, each step with its symbol, what was rolled and its modifiers.
- **The live strip** is **one row, never wrapping:** each step is a symbol, only the current one glows and shows its name, finished ones fade, and extra steps scroll. It shows in day-by-day modes, and in turn-by-turn modes only on turns when something falls due.
- **Checks and their modifiers.** Dice stay at the table: a prompt shows only the rolling instructions, the chance with its modifiers already counted ("Roll 1d6 · lost on 1–3"), and **Hit / Miss** for a two-outcome check (ruled 2026-10-30, session 2, S2-2, replacing D2's Enter roll there) or **Enter roll** where the number matters. The GM asks players out loud who rolls; the app has no who-rolls choice (ruled 2026-10-30, D2). Every prompt keeps its list of modifiers with their source (confirmed 2026-10-30, A13): from the rules (terrain, weather, roads), from the party (their abilities, through `modify` hooks; and the pack's modifiers keyed to the party, ex-2 and ga-3: a class or skill in the group, or one character's own, which add or set the faces, the best for the party winning, and name who: "1 on d6 · a Reed Witch in the party", "Only on 1 for Ash · a Mire Stalker"), or by hand (**+ Modifier**, GM only: a sheet with **−1** / **+1** chips and an optional note, one tap applies; logged with the result; ruled 2026-10-29). A location's own check replaces the mode's while the party is there. Either one counts as the encounter check for the GM's own encounter-check reminders that period, so the GM is never prompted twice; a lost check doesn't count (ruled 2026-10-29). "That period" is one advance: a day-long step's single wandering check marks all of that day's GM encounter-check reminders done, and **Check again** stays available (ruled 2026-10-29). Checks falling due together prompt in procedure order, each merged with its count. Checks no step runs are placed by their `when`: `start` before the procedure, `middle`, `end` or no `when` after it (ruled 2026-10-29). A terrain chance reads "1–2 on d6" (the die as in 07, `chanceDie`).

A later step that references the same check (a camp reusing the day's wandering check) shows **Checked this turn · Check again** in turn modes and **Checked today · Check again** in day modes (the words follow the mode's step; ruled 2026-10-30): one optional tap, logged (Verbose) when used.

- **Sides** (ns-1, ruled 2026-11-05, `design/rulings/m6-named-sides-2026-11-05.md`): every fight starts with two sides, the party's and the foes', and plays as described here. The GM may add a side from Add foes (**Side:** Foes · a new side, named after its group). A side has a **stance** toward the party (friendly · neutral · hostile; one tap to change, logged, Undo) and its own way of **taking turns** (its own turn · with the party · sits out; by default friendly acts with the party, hostile and neutral take their own turn: a neutral side takes part like any other). Who a side fights isn't modelled: the GM picks targets. In side initiative with more than two sides acting, the GM taps the sides in order (the last implied) and ends each one's turn; the round advances when every acting side is done. Players see a heading per side by name; a side's stance stays the GM's unless shown. End fight lists outcomes per side; XP waiting counts hostile sides by default.
- **Several fights** (M6; ruled 2026-10-30, DG15): with a split party, each fight is its own record (round, order, foes, HP). The GM's fight screen has a **switcher**; one fight is run at a time and the other pauses exactly where it was. Each player sees only their own group's fight.
- **The round** (M6-2, ruled 2026-10-26; turns and rounds revised 2026-10-29 after the fight dry run): a header "Round N" with the minutes elapsed, quiet. The pack's combat sequence shows as a one-row reference strip whose current step follows whose turn it is (it's never tapped through); the current step is in the display size with a glow, no underline, and the steps are the pack's own (a pack without a sequence shows one step, "Actions"; reviewed 2026-11-01, `design/rulings/m6-fight-screens-review-2026-11-01.md`). **Turns end by tap and the round advances by itself:** when every turn is done, the next round starts automatically, in initiative order: the clock advances, timers tick, end-of-round reminders and dying effects come up (logged). The GM can always end any turn or the round: **Next round** stays as the GM's override (phone: the sticky bar; tablet: top right of the controls column); undo is from the log, with no confirm. **Nothing nags:** nobody is reminded to end a turn. Players see the round and whose turn it is. Budget: see 06, Key journeys.
- **Initiative.** Dice are rolled at the table.
  - **When initiative is rolled** follows the setting (07, `initiative.rerollEachRound`): every round, or once per fight. The round-start **which side won** tap appears only when the rule re-rolls (and once at the start of a fight otherwise); ties follow the pack (`ties`). The same side can act twice in a row.
  - **Side mode (default):** any player taps **End our turn** for the party; the GM ends the foes' turn. After both, the next round starts by itself. No numbers are entered. This replaces the GM's Acting now taps as the routine step (ruled 2026-10-29).
  - **Individual mode (campaign option):** the GM (or each player) enters each final number on a big pad; the pad shows each character's modifier as a reminder. Settings for this mode: number range, high or low first, tie-breaker. Missing entries act last; nobody blocks the table. Each player taps **End turn** for their character; the GM does so for each foe or group (ruled 2026-10-29; renamed from Our turn's done and Done the same day, so every button starts with a verb).
  - **Delay** (ruled 2026-10-29; reviewed 2026-11-01: on the **Player screen only**, and only in individual initiative — side initiative needs no tracking): a button on a character's turn, where the rules or the GM allow it. It sets a visible **Delayed** flag; the character can act later, including during the foes' turn. The flag clears when they act, or at their next normal turn.
- **The fight's time and the initiative modifier** (ruled 2026-11-05, `design/rulings/m6-engine-initiative-and-time-2026-11-05.md`): with no round length in the pack, a fight takes **one turn** in all, added at its end (End fight, or We run's result); round timers still count rounds (fe-2). In individual initiative the entered number is final: the actor's modifier is shown beside the pad as a reminder and never added by the app (fe-1).
- **No telegraph state** (M6-2): nothing about what a foe will do next is entered, stored or sent; the GM says it at the table.
- **Foe nudges** (M6-2a, GM only): each foe group shows one or two muted lines from the pack's or adventure's text (behaviour, wants, tactics, how it fights), chosen by the fight's state when the pack tags its lines (at the start, winning, losing, below half, alone, leader down), else its first lines; **More** opens the rest (behaviour notes, abilities, the action menu as reference, the tactics table). Moments the GM might miss show as a ▲ line (the pack's triggers, morale). Limited abilities show as dots, tapped when used and reset as the pack says. **Roll tactics** appears only when the pack has a tactics table. No typing; never shown to players.
- **Who enters what** (M6-1, revised 2026-10-29 after the fight dry run):
  - **Players change their own character's hit points, damage and healing alike; the GM can change anyone's** (mp-10, ruled 2026-11-05, `design/rulings/m5c-magic-in-play-2026-11-05.md`; it reverses the 2026-11-01 review's "the GM enters all party damage" and returns to the fight dry run's ruling 6). A hireling's or a conjured companion's are changed by the employer's or the caster's player. The GM can say "you were all hit for 10" and each player changes theirs. *(Earlier: each player recorded their own character's damage; a hireling's by the employer or any player while the employer was Down.)*
  - **Damage to foes is the GM's job.** "Players enter damage to foes" is removed from M6 (parking lot, 08). A player's **attack starts from the weapon** (reviewed 2026-11-01): tapping a weapon at hand on the Player tab opens its prompt as a **pop-up** (✕, a tap outside or Escape closes it at once, nothing logged; an accidental tap costs nothing) with that attack type's modifiers and a row of foe chips (AC where revealed); tapping a chip gives the roll line, and the choice shows on the GM's screen ("Bram → Bog lurker 1") and pre-selects that foe on the GM's damage pad. A foe tapped on Scene (optional) pre-selects its chip. Skipping it is fine: the GM picks the target by hand.
  - Every entry is logged with who made it, and the GM can undo it.
- **GM mirror** (ruled 2026-10-29): the GM taps a foe, then a character, to see the foe's attack and what it needs ("d20 +1 · hits Bram on 14+", worked out from the character's AC).
- **Damage and healing** (M6-3, ruled 2026-10-26):
  - Foes in a group are numbered ("Bog lurker 2"); numbers never reshuffle, and players see the same numbers. Adding to a group already fighting continues its numbers.
  - **HP bar** (the GM's view of foes; characters later): a segmented bar, one segment per HP up to 12 and one per 5 HP above 12 (a part-lost segment fills partly), with "N of M"; never a plain bar.
  - Players see "took N damage", "unhurt", statuses and Down. Combat setting **Players see damage on foes**: numbers (default), words (hurt / badly hurt) or nothing. Big groups collapse their unhurt foes to "N more unhurt".
  - **The damage pad** (players for their own characters and hirelings, the GM for anyone): titled "Damage or heal", with the targets named (each removable with ✕), Damage / Heal, and a **stepper −5 −1 [N] +1 +5** that starts at that person's last amount (tap the number to type a big one); the button names the result: "Deal N to <target>", "Deal N to each" (the GM's), "Take N damage" or "Heal N". With bonus HP, the pad shows the split ("3 from bonus HP · 2 from HP"). There are **no fixed quick amounts** (they go stale as characters rise; this replaces the HP quick chips). **Area damage:** only the GM's pad has **Add a target**. The pad has no maximum (crits are said aloud; M6-9).
  - **Track HP for everyone. Monster HP is hidden from players; damage taken and statuses are public.**
  - **Bonus HP** (temporary HP; ruled 2026-10-29, 11 G-23): a character carries bonus HP {amount, source, optional timer}. Damage takes it first (the pad shows the split); the HP bar shows it as a separate band; it ends on its timer or at 0. The main path is the granting spell, ability or item (M7; 07, `grantsTempHp`); a quiet **Add bonus HP…** in the character's ⋯ covers the rest (M6).
  - Statuses and stances (defensive, all-out, from the pack) show as status symbols. **Lights in a fight:** "Drop light" (it lands burning and can be picked up) and "Put out".
  - Theatre of the mind: nothing assumes a grid (grid combat is a later release).
- **Statuses:** pick from the condition library or type one; an optional duration in rounds ticks automatically. Timed effects on monsters and areas (X-3) arrive with M6.
- **Foe cards: + Status and Note** (ruled 2026-10-29; + Status is B6's pop-up from the M5 gate: durations on one row, the effect under each name, families from the pack, typed ones as custom statuses with What it does): every foe card has a quick **+ Status** (from the setting's conditions or typed, optional round timer) and **Note** (GM-only by default, can be shared), each one or two taps from the card. Called shots and the like are handled this way. Subdual damage stays R2 (11 G-14); until then, use a status or a note.
- **GM-secret timers:** a status or effect can be marked secret (e.g. a potion's duration the GM rolled). Players see that it's active; only the GM sees what's left.
- **Tap any combatant** (PC, hireling or foe) to open its panel over the controls column; party and foes never move (06, Fight layouts). The panel is where **Damage or heal** lives: there is no separate button (reviewed 2026-11-01). Foes: stats, Damage or heal, behaviour, ability dots, triggers, **Mark as**, source. Characters and hirelings: class, race and player, HP bar, AC and attack, Damage or heal, statuses with time left, light, saves, spells and abilities, Full character sheet. Back with ✕, a tap outside or Escape; tapping another combatant swaps the panel. Stat blocks open the same way on a phone, as a sheet.
- **Add foes** (M6-4, ruled 2026-10-26; GM): one **Add foes** sheet.
  - A search field at the top always filters all monsters. Below it (the search never opens the keyboard by itself, A4), two open/close buttons, each with a symbol, its name and ▾/▴, **Encounters first** (reviewed 2026-11-01: the GM picks from a table or searches far more often than browsing), then **Bestiary** (every monster, grouped by the pack's monster types, collapsible, with counts and source tags, like Add item) and **Encounters** (the encounter and wandering tables, the current table first, others collapsed; a row picks its monster with its how-many dice filled). Opening one closes the other. What's open on arrival depends on the way in: from an encounter check's Hit, Encounters on the current table; from "+ Add a foe", both closed with the search ready; otherwise both closed. **ⓘ** on every row opens the full entry (a side panel on a tablet, a sheet on a phone) with Add inside.
  - After picking: **how many** (the pack's dice shown, a stepper starting at the average; the app never rolls); **Hit points**: Average (default; Combat setting **Monster HP**) · Roll each (one quick screen of boxes, the next opening on its own) · Roll once. Foes whose Hit Dice vary (`hpVaries`) first ask "How many HD?" with one tap per option. **Modifications** from the setting (only when the pack has them; they apply their stat changes). **More options** (collapsed switches): **One is the leader** (foe 1; feeds morale) · **Hidden from players** (never sent to players' devices; Reveal in one tap) · **Arrives in N rounds** (added hidden, with a reminder and Reveal on that round; players never see a countdown).
  - The primary button names the result ("Add 4 Bog lurkers"): they join the current fight's foe list (or start an encounter), the sheet closes, the group highlights briefly, and a toast says "Added 4 Bog lurkers · Undo". Allies: **Join the party's side**; hirelings join automatically. Budget: from a table row with average HP, 2 taps plus stepper taps.
  - Monsters from another pack's behaviours (07, overlays) show their numbers from the stat block and "Behaviour from <pack>" with its source. When a name matches and nothing links it yet, Add foes asks once per campaign whether to use that behaviour; nothing links silently.
- **Down, dying, dead, fled, surrendered** (M6-5, ruled 2026-10-26; characters revised 2026-10-29 after the fight dry run):
  - *Characters and hirelings:* **no pop-up.** At the setting's threshold the character is marked **Down** quietly, for everyone, and the player announces it at the table. On the Player tab, Down is a Status ring among the character's other statuses (pss-7, 2026-11-27). While Down (or dead), their pack and purse are open to the other players (see Inventory and encumbrance). **Tapping a Down character opens the death panel**, built from the setting's death rule (07, `death`):
    - **Plain rule** (for example, at or below a set HP the character is dead): the rule's text, **Dies** (the M4b death flow; mid-fight, making a new character waits until the fight ends) and **Not yet** (fiat, in ⋯, logged).
    - **Dying rules:** the rule's text, the rounds so far and when death comes, **Helped** / **Healed** / **Stabilised** and **Dies**. Any player or the GM may tap **Helped**, and **Healed** or **Stabilised** where the setting defines them (ruled 2026-10-29); each tap is logged and can be undone. Only the GM marks a character dead. Per-round effects happen by themselves at each new round: an automatic HP loss, or a prompt for the death roll (**Dies** / **Survives**).
    - **Helped** follows the rule: a wake-up timer from a roll the GM enters, or HP restored plus a permanent ability loss rolled at the table, the result entered (07, `abilityLoss: { roll, enter: true }`; ruled 2026-10-29). Helped alone doesn't clear Down while a wake-up timer runs; Down clears when HP goes above the threshold or the timer ends.
    - There's no "keep dying" button. Everything is logged and undoable. The panel covers both test settings with their death's-door option off and on (four cases). HP goes below zero only when the pack allows it. Non-lethal damage (when the pack's option is on): a Lethal / Non-lethal switch on the pad, a second marker on the bar, and "Subdued" at the threshold.
  - *Foes:* Down on their own at 0 HP (logged with who). The pad's **Mark as**: Down · Dead · Fled · Surrendered (Down stays alive for capture until marked Dead). Players see what their characters would. Fled foes are remembered (End fight lists them; a "Fled earlier" group sits at the top of the Bestiary; a "went where" note is optional). All four count toward morale.
  - Without the pack's death fields, the panel shows "0 HP: dies?" with Dies and Not yet.
- **Morale** (M6-6, ruled 2026-10-26):
  - **Morale prompts come only from the setting's rules** (ruled 2026-10-29): every trigger the pack states is modelled (07, `morale`). Reminders such as "leader down" (Add foes' leader) or "employer drops" appear only when the pack's rules include them; the app never invents a trigger (this retires the app's own reminders and the **Extra morale reminders** setting).
  - A trigger is a **pop-up prompt** (reviewed 2026-11-01: not a line on the card): the trigger's name, "check N of M this fight", then the check below; **Skip** closes it (once per group; the pack's limits respected). The check shows the chance first ("Roll <dice> · they break on N or more"), then the target's parts: the score, each modifier with who added it (the GM's **+ Modifier**; pack modifiers only where the pack states them), and the target; "Check 1 of 2 this fight"; **They hold** / **They break** / Skip. On a break: the pack's result text, then **All flee** / **All surrender** (the Mark as states in one tap) or decide one by one. Enough passes gives "Fights to the end" (no more reminders); scores that never check or always break apply.
  - **ⓘ About morale:** the pack's short explanation, when to check (every trigger, each with its source tag), the limits, and the source line. Packs without the fields show their written rule and no automatic triggers.
  - Hirelings use the same flow with loyalty. Players see nothing of the check. Budget: 2 taps (+1 on a break).
- **Prompts** (M6-9, ruled 2026-10-26): a player taps only to record something that changes the game (damage dealt or taken, a spell spent, an item used); everything else on their screen is reference they can ignore.
  - **Attacks** (CS-8), in the campaign's AC style, when a player taps a foe (optional; revised 2026-10-29): with the foe's AC known, the panel shows the roll first (ascending: "Roll d20 + N · hit on a total of AC or more"; descending: "Roll d20 · hit on N or more"), then the sum (the attack figure, the foe's AC where it applies, each modifier with its source; players add situational ones with + Modifier). Before the AC is known: "Roll and tell the GM" (the GM always sees what's needed). The tap marks the foe as that player's target on the GM's screen and pre-selects it on the GM's pad; the player records no damage to foes. Close with ✕ or a tap outside.
  - **Saves** (CS-3): the GM may **Call a save** (who, which save): each target's screen shows their target built from their save and each modifier with its source, with **Saved** / **Failed**, answered to the GM and the log. Optional: the GM can just say it.
  - **Natural rolls:** where the pack states them (07, `naturals`), save and skill prompts show them as text ("a 1 always fails").
  - **Crits:** no natural-20 or natural-1 buttons and no house-rule automation; players say "crit" and the table resolves it. Crit and fumble tables are one tap from the GM's controls, only when a pack has them.
  - **Spells:** no casting declaration; casting is one tap unless there's a real choice (see Spells); each spell's rules pop-up has **Spent** (crossed out like a cast spell) and shows the pack's disruption rule (its `note`) for reference. From M7 a hit caster's **Spell lost?** line sits on the damage pad (see Spells).
  - **Chance…** (GM): a chance in 6, a d20 target or a percentage ("Roll d6 · success on 1–2"); Success / Failure logged, with an optional note.
  - ◈ **Intents-first rounds** aren't included for now; Francis decides after seeing combat without them.
- **Ending a fight** (M6-11, ruled 2026-10-26; first version):
  - **End fight** (the party stayed): no confirm, undoable (toast and log). A summary: the time (the rounds already on the clock, topped up to the pack's fight length: "rounded up to 1 turn"); foes by outcome (dead; fled, to the Bestiary's "Fled earlier"; surrendered; **captured**, to a **Captives** list on the GM console until released); **XP waiting** from the foes the pack counts (defeated, fled, surrendered; held for M7's awards, adjustable there); **loot** (the stat blocks' treasure lines as reminders; **+ Add loot** opens the loot picker (a search that finds nothing offers **Add "<typed>" as a one-off**; see Inventory and encumbrance); **Send loot to the party** or **Finish without loot** (renamed 2026-10-29); an optional log line). Players get the **Loot to share** strip (Claim / Put in stash / Leave behind; unclaimed goes to the stash at session end). Then back to Explore. Rolling treasure types lands with M7.
  - **We run** (revised 2026-10-29 after the fight dry run): on the GM's controls beside End fight **and on the players' screen**: any player can call it for the party. The GM resolves it with the setting's pursuit rule (07, `pursuit`): an **Escape** step; **Drop food or treasure** (pick items; removed from packs, logged; the pack's chance to stop pursuers shown); **Got away** ends the fight with no loot step and no XP unless the pack says otherwise; **Caught** returns to the fight. **We run can be undone** (Undo toast and the log): Undo returns the party to the fight exactly where it left off (round, whose turn, statuses, timers, HP, foes and their states).
- **Dry runs** (M6-12): the fight's journeys (06) get tap and screen budgets and click-through tests; before M6's add-ins and ending are final, two paper dry runs (the fight dry run was held on 2026-10-29; its rulings are in this section and in `design/rulings/fight-dry-run-2026-10-29.md`): a scripted 5-round fight (target: at most one tap per player per round on average) and creating GM add-ins (a table, a tactics table; the tables dry run was held on 2026-10-29, its rulings in GM add-ins below).

## GM add-ins (optional, GM console only)

- Monster disposition, surprise, and encounter tables.
- Dice stay physical: the GM rolls (or asks a player to roll out loud) and taps the matching row. The app never rolls.
- Players are never prompted on their screens; the GM asks out loud and types results. GM-secret rolls stay on the GM console.
- **Tables in M6** (M6-10, ruled 2026-10-26; revised by the tables dry run, 2026-10-29; **aligned with the M5 gate, 2026-11-01**, `design/rulings/m6-gate-alignment-2026-11-01.md`): the **Encounter tables ›** row (B2) shows in Explore, Encounter and the fight's Controls column and opens the full-screen list; the GM taps the rolled row; **no typed roll** (the old "type the roll" is gone; Go to number stays for long tables). **Table library ›** is the table library and the way into the prep space. Each row says what tapping it does: **Add** (a monster with its how-many dice, into Add foes), **Table ›** (opens the sub-table in place, with a trail back) or **Event** (to the log).
- Two-dice tables show as a grid (the first die across, the second down); weighted 2d6 tables as ordinary 2–12 ranges. Tables can point to another table (terrain → sub-table).
- **Three sources, one list:** tables from setting rules, from adventure packs, and tables the GM builds. Setting and adventure tables are imported (JSON/Markdown, usually built by the converter skill from your books); each campaign shows the tables from its attached packs.
- **Quick table builder (M6; scope widened by the tables dry run, 2026-10-29, from a scan of 6 pack files: 167 tables, about 2,000 rows):** name, die, one row per line (ranges split evenly, editable; a range typed at the start of a line, "2-4", sets it; gaps and overlaps warn, never block; pasting rows from notes works, read leniently on format and strictly on meaning); one or more uses from the registry (07, Table uses registry). **Per row:** a count; a monster link, or **New monster…** (saves a homebrew stat block with effects and modifiers); a table link (nested); a note, tags and GM-only parts; the Add foes options (Modification, leader, Hidden, Arrives in). **Per table:** several columns, groups, and tens-and-units dice. Matrices and lookups stay pack-only: the in-app editor may edit a pack's lookup or matrix table on a copy, but never makes a new one from scratch (to get one, copy an existing table and edit the copy; ruled 2026-10-29). Saved to the campaign's homebrew, logged.
- **Copy** (a new table) or **Edit** (your version replaces the pack's in this campaign, by the M3 stacking; the original stays untouched). Kept: it was clear in the tables dry run (2026-10-29).
- **Uses registry:** grouped and collapsible, the campaign's most-used uses first. The `encounters`, `fights.tactics`, `fights.crit` and `fights.fumble` uses (07) drive the Encounters list in Add foes, **Roll tactics** and **Crit · Fumble**.
- **Applying a table** (ruled 2026-10-29): the GM pulls up a table from Explore or from the fight controls and applies the result to the current scene. Places and areas can carry default tables; the GM's pick overrides them.
- **Tactics tables are linked on the monster** (its stat block's `tables.tactics`, 07); Roll tactics uses that link. Checked in live play at the M6 gate.
- Results stay on the GM console. Only what the GM reveals (e.g. adding monsters to the fight) reaches anyone else.
- Each add-in can be switched off in campaign settings.
- The look is approved; the process is proven by doing: a dry run of creating add-ins joins the M6-12 dry runs before it's final.

## GM to players

- **Messaging** (ruled 2026-11-01, M5 gate B3; mockup `design/mockups/m5-gate/b3-messaging.html`; replaces Send, From the GM and any send-to-GM; supersedes the 2026-10-24 Keep in Handouts / Burn after reading choice and D26): one private feature **between the GM and a player only** (no player-to-player messages, no Everyone: what everyone hears is said aloud), for secrets and attachments. A thread shows the messages (newest at the bottom), a text field that never takes focus by itself (A4), **Attach** (Handouts: anything revealed or kept; **From the adventure**, GM only, M8b: a read-aloud crop, a clue, an image; **A file**: a picture from the device, **the GM only, up to 10 MB** (ruled 2026-11-01, g4; players send text only; the database and the bucket refuse a player's file and a larger one)), one switch **Disappears once read** with the plain note "This message disappears once they've read it" (off by default; the recipient sees it until they close it, then it leaves their device with its attachment; the GM's log keeps the text), and **Send** (the screen's accent button; Undo for the toast's time, 06). ## Adventures (M8b)

Ruled 2026-10-24; the format is in `07-content-packs.md`, Adventure packs (format version 3). Adventure content never reaches players' devices unless the GM shows it.

- **Start adventure:** one tap, logged; sets the adventure's day 1 to the campaign's current day.
- **Location browser:** every place from region down to room; search by key or name, and a "recently visited" list, so any room is two or three taps away.
- **Two layers per location:** what players notice (a few short lines: sights, sounds, smells; who is visibly there, described but not named until introduced; obvious exits; a shop's wares and prices) and the GM layer (notes, clues, secrets, stat blocks, page crops).
- **Opening a location for the party:** one tap, separate from setting the current location; shows only what players notice, and the GM can edit it before showing. One open location at a time, until closed or another is opened. Players see the location's player name; without one, "Unknown place" until the GM names it.
- **Travel:** pre-fills the route's time; the GM can change it before confirming. Logged and undoable. Checks that fall due along the way show once, with a count.
- **Day / Night:** a switch on the time strip (one tap, logged, shown to players on Scene); the GM decides when night falls.
- **Encounter checks** sit on locations (a child location can have its own; `onlyAt` day or night; `byTrack` changes the chance with a track's value). **Check now** runs one on demand; the **active check** shows on the Explore panel ("Abbey · 1–2 on d6 each turn"). Dice stay at the table.
- **NPCs:** **Introduce** is one tap and logged; introduced NPCs appear in Handouts → People with their name and description. **Status** (alive, dead, missing or absent; friendly, neutral or hostile) is logged and GM only unless the GM shares it.
- **Shops:** buying in a shop charges the shop's price, not the item's list price. Stock counts: the GM enters rolled quantities when the shop first opens, buying lowers them, an empty line shows "Sold out". A price can be text (the GM confirms the sale by hand). Services take coin and write a log line. Selling follows what the shop buys, and the GM confirms the amount. Players browse an open shop until the GM closes it.
- **Rumours:** told ones are marked (dimmed for the GM); rolling a told one offers "Already told: roll again?". A rumour's truth is GM only, never sent. **Send** shares a row's text in one tap and keeps it in Handouts by default.
- **Tracks** (countdowns) **with rosters:** each roster entry is an NPC or an inline name (with an optional note); **Make NPC** on a roster entry (GM) turns an inline person into an NPC in the campaign's homebrew, keeping their roster place and state; states are defined by the pack, and each says whether it moves the track. Several at once: the GM enters how many, then the roll for each, or taps names; a rolled entry already taken moves to the next free one; the whole thing is one logged change. A GM-only nudge (`onTick`) on each change; manual ticks any time. Thresholds notify only the GM.
- **Timeline:** day-based beats remind the GM when their day comes; the adventure overview lists what's coming. Conditional beats stay as GM notes with their page.
- **Pre-mades** are offered at every character creation (joining, a new character, a replacement after a death): any from the campaign's attached adventures that isn't claimed or dead. Submitting claims it; declined or cancelled, it's free again. A pre-made whose character died is never offered again unless the GM frees it by fiat (logged). It fills the guided form and the player edits it. **The GM always approves before play, even when character approval is switched off.** A missing class falls back to freeform with the details kept as notes. The GM can hide a pre-made.
- **Reveal images:** whole or a GM-cropped rectangle; "Show players" sits on locations, NPCs, stat blocks and items that have an image. Page crops are never revealed.
- **Handouts:** revealed images, text kept from Send ("Keep as handout": rumours, clues) and **People** (introduced NPCs), in two groups: **From your adventure** and **Your uploads** (the GM's direct uploads). Opens from Scene; each reveal shows one quiet card, then joins the list. A party journal is later.
- **Prep mode** (widening into a **GM prep space** for any campaign, ruled 2026-10-29: tables, encounter tables, treasure, NPCs, planned encounters, rooms and areas, traps and items; designed in the G-05 session before M8b's design, 11): a GM walk-through of the adventure's locations in page order on a tablet, with each location's summary, clues and player view beside its crop, inline editing and a **Reviewed** mark. Edits save into the campaign's homebrew, so updating the pack later never loses them.
- **Turning mechanics off:** each adventure-specific mechanic (each track, roster, `byTrack` and the timeline reminders) is its own optional rule (one switch each); the optional-rules list shows them together under an **Adventure mechanics** heading within their adventure. Entries linked to a switch follow it, and pieces that depend on a track follow the track (a `byTrack` chance falls back to the base chance while the track is off). Off turns it into a GM note with its page. Automations every adventure uses are switches in **Campaign → During play**: Travel moves the clock, shop stock counts, told rumours marked, the active check shown. Defaults are on, and every switch says what "off" does.

## Voting mini-app

- A standalone tool. Votes are optional except where listed below.
- The GM or any player taps **Call a vote** → question, options (or Yes/No), open or secret ballot, optional close time → it **broadcasts** to every screen as a dismissible banner.
- Players vote in 2 taps; the GM does not vote.
- The GM can **sanction** (confirm) or **overrule** each result. Results are logged.
- The app requires votes for charter changes (unanimous), joining the company, and creating or assigning titles.
- Joining the company, creating titles and choosing title holders pass by **simple majority** of charter members. Charter changes stay **unanimous**.
- Secret ballots are hidden from everyone, including the GM and the database owner. Everyone sees who has voted and, once closed, the tally. The log records that a person voted, never their choice. Secret ballots can't be changed once cast; open ballots can change until the vote closes.

## Charter

- Each company has its own charter.
- The **founding version** is written freely when the party forms: any player writes it during campaign setup, without a vote, until the first session starts. After that, any change (including restoring an old version, renaming the party or changing its sigil) is a **proposal** that goes to a vote of all players and passes only if **everyone** agrees. Failed proposals stay in the log; the charter is unchanged. **Before M8's votes** (M7b-1): a proposal lands in the GM's Waiting for you list and the GM applies it, logged "proposed by <player>, applied by the GM"; M8 switches on unanimous votes with no rework.
- Only players vote on the charter; the GM and hirelings don't. The GM can override a charter vote with fiat (sealed, logged, reversible).
- The charter holds the **party name** and **sigil** (an uploaded image). The name and sigil show on the charter, Scene and settings. Tap the **sigil** to upload a new one; tap the **name** to rename. Both are proposals that go to a vote.
- **Share distribution:** only the **party fund %** is set in the charter (with a stepper). Every charter member gets one share unless a named exception says otherwise. Animals and mounts get no shares; **hirelings are paid per their contracts**, not the charter. Split Loot reads this section.
- The freeform section, **House Rules and Customs** (funerals and heirs, house rules, anything else), is plain text.
- Each accepted change is saved as version N; earlier versions list with **Restore**, which proposes them as a new version.
- **Members and titles** (button on the charter): list of charter members and their titles; "Ask to join the company"; "Propose holder" per title; "+ Propose a new title". All go to a vote.

## Titles (hats)

- Every company starts with **Treasurer** and **Archivist**; only these two carry powers in R1 (see `03-roles-permissions.md`).
- Players propose new titles (names only) and who holds any title from the charter's Members and titles. Both go to a vote.

## Fiat

- Always-visible GM button, plus a seal action on any item. Pick the target, set the ruling, optional reason. Logged with a seal; GM can roll back.
- **M2:** the GM using a player's own power on that player's character (editing their sheet, HP or portrait) is logged as fiat automatically; editing a player's sheet offers an optional Reason. The log shows the seal, the word "Fiat" and the reason; only the GM can undo it. The Fiat button comes with the GM console.

## Retainers, holdings, organizations, projects (R1 basic)

- Hirelings: contract terms, wage, level, class/role, stats (fields), rules notes, loyalty/morale, notes, inventory. They join combat and marching order like any actor.
- Wages and recurring expenses can repeat **per day, per adventure, per week, per month or per session**.
- **Personal recurring expenses:** players can set recurring expenses on their own purse (e.g. a retainer's food and lodging); they show under the player's own Due list.
- **Groups:** a hireling entry can have a **count** (e.g. "Light footmen ×20") for mercenaries; casualties and desertions lower the count. A campaign **wartime** switch doubles mercenary wages.
- **Retainer XP (R1):** hirelings marked as retainers join the XP split (Award XP's Who shares) and level up through the same flow as PCs, taking the pack's share (set by the setting rules). Normal humans choose a class when they first gain XP.
- Holdings, organizations, long-term projects: name, owner, location, status, upkeep, notes, linked actors. Deep features are R2.

## Downtime

**Redesigned 2026-11-02** (`design/rulings/m7-downtime-2026-11-02.md`, dt-1 … dt-45; mockups `design/mockups/downtime/01–07`): the arrival card, one significant action plus upkeep, proposals with terms, progress bars in R1, rolls by band, troubles with clocks, time by any amount with summaries, lodging and stored places, Spend…, and the notes and information sheets. The full text replaces the lines below in the M7 downtime plan's step 0 (`plans/m7-downtime.md`); where they differ, the ruling wins.

- **Activities are text threads.** A player proposes an activity in free text. The GM replies in text and can attach **terms** (time, cost, what happens at the end, how progress is measured). The player **accepts**, **asks for a change** (text), or **declines**. Every message is logged.
- **Accepted activities stay active across sessions,** with play sessions in between, until the GM resolves them with a note.
- **Progress** measures: ~~R2~~ **R1** (dt-19, 2026-11-02): segmented bars with the current and next step.
- GM view groups threads: **Needs your reply · Waiting on players · Active**. Players see their own threads in full; the rest of the party sees only titles and progress.
- A **Completed** section lists resolved activities, collapsed by default (GM and player views).
- Leveling up stays a downtime activity (with the auto-fill preview).
- **Revealed this downtime:** check results logged during the last session become visible to players, in the log (the Scene card was dropped at the M5 gate, B17, 2026-11-01).
- **Split Loot**'s Treasure XP goes into the XP waiting pot as a "Treasure · N" line, only when treasure gives XP (see Purses and party fund; awarded in **Award XP**, see XP and levels). Non-GMs running Split Loot see share sizes, never purse balances. Encumbrance does not apply in downtime; carried treasure counts again when the next adventure starts.
- **Bonus XP:** in Award XP the GM can add bonus XP to a character or the party, each with a reason shown in the log. Bonuses sit on top of the split.
- **Where money is:** each purse and the party coffers are split into **carried** and **stored**, with named places (a bank, a strongbox, a cache). After a split, shares land in the purse or coffers; players then move coin between places as often as they like **during downtime**. **During an adventure**, taking money out of storage needs the GM's approval and puts it in the player's inventory (where it counts for encumbrance). Stored amounts are private from other players; the GM sees them.
- **Places:** anyone can add a storage place. A new place goes to the GM as an **Approve / Deny** prompt (the GM can attach a flat fee or an ongoing rate). Approved: it works as normal. Denied: the player is notified and can try again after talking it through with the GM. No warning text is shown to players in advance.
- **GM sees what players see.** Everything visible to a player is visible to the GM.
- **GM can edit any player sheet as if they were the player** (via fiat), e.g. setting a bank balance to zero after a collapse. Logged with the fiat seal and reversible.

## Scene tab (shared view)

- Open to every player on their own device. On a tablet or small monitor it uses three columns; on phones, one column. No TV layout. No GM-only data, ever.
- What it shows follows the GM's mode (see Explore, Encounter and Fight): time (turn, day, round), initiative with the acting side highlighted, foes' damage taken and statuses (monster HP hidden), and the party in marching order (one column) with HP and statuses.
- The phone layout follows the GM's mode like the tablet: Explore (marching order with light and dark-sight cues, log) and Fight (whose turn, party, foes' damage, log).
- The party sigil at the top opens the Company page.
- Light and dark sight show only as visual reminders: a glowing ring with a flame mark for a lit light, a dashed ring with an eye mark for dark sight. Details appear on tap.
- **Below the place** on the players' table view (ruled 2026-11-03, SC-g6-1; 06, "Dungeon on Scene: the players' table view"), in this order: the hour track with its public events, then the recent log lines; the procedure reference in the players' words opens from the time band. Nothing else is added to the steady state.
- A few recent log lines, newest first, with no full-log link. The full log opens from the top row's Log button for everyone (a bottom sheet on a phone, a side panel on a tablet; filters, search, verbose view), where players tap any entry to annotate it or add a standalone note; the screen behind keeps its place. There is no Log tab (ruled 2026-10-23).

## Offline

- Everything you can see is cached. Offline you can read everything and edit your own character; changes sync when back online. How it looks (ruled 2026-10-25; 06, Offline and sync states): an "Offline · N waiting" pill with a details sheet, "waiting" tags on your unsynced values, age labels on others' values older than 2 minutes, "Catching up…" on reconnect, and a toast plus a ✕ log entry for a rejected change. Nothing is hidden offline; what can't work explains why on tap.
- **The GM offline** (ruled 2026-10-25, M9): the GM's own commands (the clock, checks, reminders, lights, marching order) queue on the GM's device and replay on reconnect, recalculated, in clock order, with a log line "GM was offline 8 min · 6 turns caught up". While the GM's device is offline, players see an ⓘ pill **"GM offline · time paused"**, cleared by that line. A second GM device shows **"Read-only: your other device is running the session"**, explained on tap. Queued commands can be undone once synced. Signing out clears the device's offline copy.

## Voice (R1)

- Dictation into any text field (notes, log, explanations) using the device's built-in speech-to-text. No commands, no AI. Includes notes and annotations in the log.

## Alerts

- In-app alerts for: vote called, downtime resolved, charter edited, you were mentioned in a note. Email in R3; SMS later.
- While a session is running, Grimoire shows no alerts or banners; everything waits in the log until the session ends. The one exception (ruled 2026-10-24): a **reveal** shows at once, even in quiet mode, as one silent card (no sound or vibration), then joins Handouts.
- The screen stays awake during a session (where the browser supports it).
- At session start, a one-tap reminder suggests turning on Focus / Do Not Disturb, with a short how-to per device. The app cannot silence other apps' notifications; no web app can.
