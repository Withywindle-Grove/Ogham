# 04 — Data Model

All IDs are UUIDs. Every row has `createdAt`, `createdBy`, `updatedAt` (library entries excepted: they belong to their pack, which has them). Money, quantities, weights and slots are integers.

**Account deletion** (2026-11-24, Francis, "yes to both questions" on #77's ⚑ 4 and 5; migrations `20261124140000_account_deletion_keeps_calls.sql` and `20261124160000_account_deletion_keeps_rows.sql`) — deleting an account (a player's or a GM's, in a live or a retired campaign) keeps every row it is linked to: each link to it that is `on delete set null` is emptied and nothing else changes. That covers `createdBy` everywhere (it was put back by `private.stamp_row`, so it silently kept the gone account), a character's `ownerUserId`, a session's and an expedition's `startedBy` and `endedBy`, a request's and a sheet change's `requesterId` and `answeredBy`, a message's `senderUserId`, a weather roll's `enteredBy` and `correctedBy`, a lost group's `rollBy`, an invite's `invitedBy` and `acceptedBy`, an asset's `uploadedBy`, and the calls' links (below). Each table's own guard and the retired-campaign guard let exactly that change through, and only once the account is gone; every other change is refused as before. The database logs each emptied link as a line with no person on it, which offers no Undo; it doesn't block the Undo of an earlier change. **Also kept** (2026-11-25, Francis, "2 a, 3 as recommended" on #84's ⚑ 1 and ⚑ 2; migration `20261125090000_account_deletion_keeps_asks_and_homebrew.sql`): a request a player asked stays with no asker (`requesterId` empties; a request a player asks still needs its asker otherwise, and a standing account's can't be emptied by hand); a request with no requester is read by everyone only when it is the party's (the GM asked, no character): one asked of or by a deleted player, and its log lines, are the GM's alone (2026-11-25, migration `20261125150000_account_deletion_orphaned_requests_stay_hidden.sql`); the messages sent to that player (a thread message's `playerUserId`, a message recipient's `userId`, both now `on delete set null`) stay with no player, read by the GM alone; and a campaign's own homebrew pack (the pack with a `campaignId`) stays with what hangs on it (its entries, hidden fields and link to the campaign), its `ownerUserId` emptied (now `on delete set null`). **Still let go:** the account's memberships, and its personal library packs (no `campaignId`, attached to a campaign or not) with their entries and links, which go just before the account's profile does. Names below are conceptual; Claude Code turns them into Supabase tables and TypeScript types.

**Hidden data lives in separate tables.** Supabase access rules apply per row, not per column, so anything only some people may see gets its own table and rule (e.g. `actor_secrets` below). Purses are already computed from LedgerEntry rows, which only the owner and the GM can read, with one named exception (ruled 2026-10-29; 03): while a character is Down or dead, the other players can read and take from its pack and purse, by an access rule on the character's state.

## Accounts and library

**User** — id, display name, email, avatar.

**LibraryEntry** (account-level content library) — id, packId (the owner is the pack's), kind (`item`, `class`, `race`, `xpTable`, `rulesSet`, `option`, `statBlock`, `condition`, `lightType`, `spell`, `spellList`, `table`, `treasureType`, `calendar`, `fieldTemplate`, `startingKit`, `hook`), packEntryId (the entry's `id` inside the pack, used when re-importing), name, data (JSON per `07-content-packs.md`). Ids are unique per kind within a pack.

**LibraryEntrySecrets** — entry id, packId, data: the fields an entry's `gmOnly` list names, and the list itself, kept apart so players' devices never receive them (read by the pack's owner and the GM of a campaign using it; split off by the database whenever an entry is written; a campaign homebrew's changes are logged for the GM alone).

**Pack** — id, ownerUserId (empty only on a campaign's homebrew pack whose GM's account was deleted; above, Account deletion), name, version, formatVersion, kind (`setting` | `adventure` | `homebrew`), campaignId (set only for a campaign's automatic homebrew pack: kind `homebrew`, one per campaign, made only by its GM), source note, notes, extraMeta (the file's meta keys Grimoire doesn't use, kept and shown), imported at (the time of its last import or update). **contentRev** (perf fix 2(b), 2026-11-07): a whole number the database bumps once per statement that changes the pack's entries or hidden fields (import, update, an edited entry, homebrew saved or deleted, a hidden field changed); written by triggers only (a hand-written value is kept at the old one); read by whoever can read the pack. The device's stored copy of the pack's entries is used only while its stamp matches. A pack groups library entries. Re-importing a newer version updates entries with the same kind and `packEntryId`, adds new ones and removes ones the file no longer has, after a preview of the changes.

**Pack map** (dec-7 piece 5m-1; 07 Adventure packs §9; migration `20261114200000_dec_7_5m_1_map_kind.sql`) — an adventure pack's `images` of type `map` are kept as library entries of kind `map`, named by their `title` (the GM's: not player-facing, so the read rule on library entries keeps them from players), each entry's data the picture as the pack wrote it less its id: `file` (the file's name, what the GM is asked for), `title`, `alt`, `locationIds` (the places it belongs to), `source`, and what else the pack said (`visibility`, `playerVersionId`, `keys`), kept for later pieces. The picture file never comes with the pack: the campaign's copy is a map asset the GM adds (5m-2). Handouts, art and crops are left out at import, said once.

**A place's map** (dec-7 piece 5m-2; migration `20261114210000_dec_7_5m_2_place_map.sql`) — `places.map_asset_id`: the campaign's copy of a map, an asset of kind `map` of the place's own campaign (a trigger), visibility `gm` when added (the GM's alone until shared). **Shared** (5m-3, `place.shareMap`; migration `20261115100000_dec_7_5m_3_map_eye.sql`, the command's log row only): the GM sets the copy's visibility to `all` (every member of the campaign reads its row and file, under the assets rules as they stand) or back to `gm`; logged, with Undo. A place two maps name shows the first; a map's file takes 25 MB of input, as the place's picture; a place made by hand has no "+ Map" row until a frame draws one (mp-1 to mp-3, 2026-11-14, `design/rulings/dec-scene-whole-2026-11-14.md`). The GM picks the file once from the device (made smaller there: 2400 px on its longest side at most; a PNG stays a PNG, a picture that already fits goes as it came) through `place.addMap` (the asset row and its file; never undone, as a place's picture) and `place.setMap` (the tie, a logged change of the place: Undo unties it). One copy per campaign: a pack's map that names several places is asked for once; every other place whose own map it is (the first of its pack's maps that names it, by entry id) finds the copy on the place that holds the tie. A place made by hand may hold one too. `places` stays the GM's to read, so the tie reaches no player. **The players' map** (P5; migration `20261122140000_p5_players_map.sql`; Francis's yes, 2026-11-22): `public.map_for_players(campaign)` sends each of the reader's groups the copy's id and name (its title) of the map of the last place shown to that group on the expedition under way (mc-39b's rule), only while the copy's eye is open (visibility `all`): the copy tied to that place, else the one another place holds for the same pack map (the place's own, else the nearest place it sits in names it: `private.pack_place_map`); nothing before a place is shown, no place id, pack entry, place name or position. A map's eye opened or closed ticks every group's signal (`private.tick_map_shown`).

**Pack person** (dec-3, town row W8; migration `20261115120000_dec_3_npc_kind.sql`) — an adventure pack's `npcs` are kept as library entries of kind `npc`, named by their `name` (the GM's: not player-facing, so the read rule on library entries and `campaign_library` keep them from players; as for every GM-only kind, a player who owns the pack reads it as its owner), each entry's data the person as the pack wrote it (role, place, `playerView`, the GM's `gm` leads and lines). Data only: no screen shows them yet.

**Pack shop** (dec-3, town row W9; sh-1, sh-2; migration `20261115140000_dec_3_shop_kind.sql`) — an adventure pack's `shops` are kept as library entries of kind `shop`, named by their `name` (the GM's: not player-facing, so the read rule on library entries and `campaign_library` keep them from players; as for every GM-only kind, a player who owns the pack reads it as its owner), each entry's data the shop as the pack wrote it (`locationId`, `services`, `stock` with each line's `itemRef`, price and availability, the GM's `gm`). A stock line's item is the bare item id, read by `shopStockLines` (`src/modules/library/packShops.ts`), the one place the `<pack>:` prefix is dropped. Data only: no screen shows them yet.

**AdventureHook and HookSend** (dec-12 piece B; pf-7, pf-7a, mc-61 to mc-64; migration `20261113210000_dec_12b_calls_to_adventure.sql`) — an adventure pack's `adventureHooks` are kept as library entries of kind `adventureHook` (the GM's: not player-facing, so the read rule on library entries keeps them from players), each entry's data its `text`, `pays`, `giverNpcId`, and two things the importer adds and export leaves out: `giver` ({ name, role, place }, found from the pack's npcs and locations as the file is read) and `order` (its place in the book's list). A **send** is its own record (table `hook_sends`): campaignId, packId and hookKey (the hook's own id in the pack; no foreign key), actorId (the character who hears it; null for the party), playerUserId (that character's player when sent), name, body and pays as sent (the GM may change them for this send; the pack never changes), clockSeconds (the campaign clock at the send, for "day N"), undone, version. Its name, body and pays keep each link mark as its words only (rp-11); the GM's sheet shows a hook's words the same way. Made only by `send_hook` (`hook.send`, the GM's, logged; one live send of a hook per hearer, a second refused in words); Undo marks it undone. **When that player's account, or the GM's who sent it, is deleted** (2026-11-24, widened the same day to the GM and to retired campaigns; migration `20261124140000_account_deletion_keeps_calls.sql`) the send stays, its playerUserId or createdBy emptied (the one change it allows besides Undo's mark, allowed even in a retired campaign), and the GM alone reads a send to a character with no player; the GM's Undo of the send still works after the player's account is gone. **Who reads a send:** the GM every one; a player a live send to the party, or to a character whose player they were when it was sent. Its log line is everyone's for the party, the player's (and the GM's) for a character. **A given rumour** (dec-12 E; mc-65, tb-1, rm-1; migration `20261114220000_dec_12e_rumours.sql`) is a send too, with `kind` 'rumour' (every hook's send is 'hook'; kept as written): made only by `give_rumour` (`rumour.give`, the GM's, logged, Undo marks it undone) from a row of a rumours table (a `table` entry with the use `world.rumours`, or the older `"kind": "rumours"`) of an adventure attached to the campaign, the row named by its range; hookKey is `<table id>#<min>-<max>`, name "A rumour" (rm-2, migration `20261115001000_dec_12e_rumour_name.sql`; gives made before it keep the table's name), body the row's `result` with each link mark as its words, pays empty. The row's `truth` and `note` are never copied: they stay in the table, which players never read, even where its pack marks it open (rm-3, migration `20261115002000_dec_12e_rumours_gm_only.sql`). Read as a hook's send is.

**CampaignRulesRevs** — campaignId, seenRev (perf fix 2(b), 2026-11-07): the campaign's **seen stamp**, a whole number bumped by the database when what a member may read changes without any pack changing: `known_items` (an item revealed), `campaign_packs` (attached, detached, moved, options changed) and `campaign_pack_secrets` (the GM's exceptions). A side table rather than a column on Campaign, whose changes are logged (a bump must not write a log line). Read by members; written by triggers only; a campaign without a row is at 0.

**CampaignPack** — campaignId, packId, packName (the pack's name when attached, kept so the campaign's log can name it after the pack is deleted), optionChoices {optionId: choiceId} (rules options picked when the pack is attached; see `07`), priority (packs stack in one order; the campaign homebrew pack is on top by default), overrides {"kind:entryId": entry name} (the GM's per-entry exceptions: entries this pack wins whatever the order; the name is kept for the log). **All exceptions are GM-only** (ruled 2026-10-29, A4; previously those for player-facing kinds sat on the link, which leaked the names of items players don't know): they live in **CampaignPackSecrets** (one row per link, same id, made and removed with it, read and changed by the GM only; its changes are logged for the GM alone). Players' devices get only the winning entries, worked out by the database, so they never learn an exception's entry name.

## Campaign

**Campaign**
- id, name, sigilAssetId (the GM changes both; no vote). Membership and GM role live only in the Member table.
- retiredAt (empty, or when the GM retired it: read only for everyone, nobody joins; the GM can bring it back)
- seasonNotNowAt (empty, or when the GM said "Not now" to "Which season?": it isn't asked again, on any GM device, until a session starts after it; ruled 2026-10-30, 05 Seasons, weather and the calendar)
- flags {flagId: true | false} (switches from the setting rules' `campaignFlags`, e.g. a war; readable by hooks as `campaign.flags.<id>`; changes logged)
- mode: `adventure` | `downtime`
- adventureMode: `explore` | `encounter` | `fight` (GM-set, broadcast to all screens; fight is a step inside an encounter)
- settings:
  - `encumbrance.mode`: `none` | `armour` | `coin` | `slot` (chosen at creation, or preset by a pack option; only the chosen one is shown; from M4b the optional-rules row "Encumbrance" decides it, ruled 2026-10-24). `none` is always offered; the others only when an attached pack or the homebrew supplies their data (07, Encumbrance)
  - `encumbrance.armour`: maxLoadCoin, movement rows [{armour: none | light | heavy, withoutTreasure, withTreasure}]; only treasure weight is tracked
  - `encumbrance.coin`: coinsPerUnit, maxLoadCoin, tiers [{label, max, effect, movement?}], overMax (optional text), miscGearCoin and miscGearCategories (optional flat weight, added once for weightless gear of those categories)
  - `encumbrance.slot`: baseSlots, coinsPerSlot (optional), tiers [{label, maxSlots, effect, movement?}], overMax (optional)
  - `encumbrance.treasureWeights`: {itemCategory: weight or null}; an item is treasure when its category is a key
  - `encumbrance.containers`: `add` (the fallback when no pack says: containers add capacity) | `hold-only` (containers only hold; max load fixed)
  - `packOptions`: not stored; worked out when read from each attached pack's `CampaignPack.optionChoices` and its `byOption` rules, after the `ruleGroups` picks below. The GM can change a choice later where the pack allows it (`changeLater`: allow, warn or never; `lock` is read as never).
  - `ruleGroups`: `{ <ruleKey>: <pack id> }`, which pack's rule counts for each `ruleKey` group (07; built 2026-11-02): empty or missing means the pack on top decides. Written at set-up (a pick from the clash callout), when a pack bringing a rival rule is attached (the standing winner is pinned so nothing changes until the GM confirms), by the GM's answer to "New choice for <topic>" (`campaign.update`), and cleared for a removed pack (`rules.detach`, logged as the fall-back).
  - `currency`: denominations [{key, label, valueInBase, countsForWeight}] — weight uses one coin count; value can be many denominations
  - `oneOffApproval`: true (default) | false: a player's one-off items wait for the GM (ruled 2026-10-24); a one-off a player adds to a character of their own that isn't approved yet (a draft, waiting or sent back: a trinket, a kit's or background's `{ name }` line) comes in approved whatever the setting, since the character's own approval covers it; moved off that character by the player, it waits again where it lands (bq3-6, built 2026-11-04)
  - `rechargeDefault`: false (default) | true: "Charged items can be recharged" when neither the item nor the setting rules say (ruled 2026-10-24)
  - `anyKit`: removed (cw-9, 2026-11-06); a stored value is ignored and starting gear offers the class's kits only
  - `companies`: true (default) | false: companies, charters, company titles and votes, and the Treasury on or off; off hides, never deletes (ruled 2026-10-24)
  - `time`: roundSeconds (default 6), turnMinutes (default 10), dayHours (default 24); roundsPerTurn and turnsPerDay are computed and stored; a turn must be a whole number of rounds; advanced option to enter ratios directly; label overrides
  - `initiative`: mode (`side` default | `individual`), rangeMin, rangeMax (optional), rerollEachRound (true: rolled every round, so the round-start "which side won" tap appears each round; false: once per fight; ruled 2026-10-29), order (`high` | `low`), ties (`party` | `opponents` | `reroll` | `simultaneous`). Neutral app default: any number, high first, GM breaks ties. "Party" means the whole party side, including companions. A GM's own initiative rule comes from their private rules pack.
  - `xp.partySplit`: GM-only setting, separate from the charter. R1 splits evenly among the characters who share (Award XP's Who shares; from M9, with hirelings, retainers take the pack's `xp.retainerShare`); shares round as the pack says (default: to the nearest, half shares up). Other hireling and companion XP shares are R2.
  - `levelUpWhen` (M7-2): `downtime` | `anyTime`; empty follows the pack's `levelUp.when` (default `downtime`).
  - `treasureXp` (M7b-1, "Treasure gives XP"): empty follows the pack's `xp.treasure`; true or false overrides it.
  - `hpRequired`: true when a sheet layout in use marks its `hp` field required (set by "Use this sheet layout", which never makes an `hp` campaign field: HP is the character's own); creation then asks for HP (ruled 2026-10-24, 2026-10-25)
  - `hideProcedureNotes`: hide the exploration procedure's note lines under the time strip (default off; ruled 2026-10-25)
  - `caller`: the caller (mc-76), a character's id, or null for none (the lead, 2026-11-14: a settings key, no migration). Written by the GM through `campaign.update`, logged ("made Wren the caller"); every member reads it, as the other settings. Shown on the caller's banner at the head of the marching order (S12)
  - `playersSeeHp`: **Show each other's HP** (renamed 2026-10-30 from "Players see each other's HP"; default true; M5-6). It promises no secrecy yet: HP moves into its own table at the start of M6 (read by the owner, the GM, and everyone only when this is Yes), alongside the Down/dead pack-and-purse read rules; that migration needs Francis's OK first (08).
  - `gettingLost`: `secret` | `open`, "Getting lost" (ruled 2026-10-30, S4-6, changing D7's always-GM-only Lost; default **Secret**, ruled 2026-10-31). Secret: the party's Lost status and its recovery roll are GM-only. Open: players see both. There's still no believed-vs-true position (D7).
  - `weatherRolledBy`: `players` (default) | `gm`, "Weather rolled by" (ruled 2026-10-30, D1; 05 Seasons, weather and the calendar)

Saving it while the clock hasn't moved (Day 1, no expedition, no clock move standing in the log) also puts the clock at that time, in one `time.start` change; once the clock has moved it only shows (ruled 2026-11-01, B13; 05 M5 gate small items)
  - `characterApproval`: new characters need GM approval (default on); off, a player's new character joins at once (and becomes their active one if they have none), except under `startLevel` `gm` when it asks for a level above the party's lowest

  - `playersReorderMarching`: players can reorder marching order (default true; the GM always can; ruled 2026-10-25, no permission bundles)
  - `monsterStats`: `learned` (default: a stat block's AC is known after the first confirmed hit and stays known; the confirmed hit is the GM recording a hit on a foe the player targeted, which shows that foe's AC to that player, and the GM can also reveal AC by hand, logged (ruled 2026-10-29); saves when the GM reveals them) | `shown` | `hidden` (M6; ruled 2026-10-25)
  - `wartime`: doubles mercenary wages (default off)
  - `log.defaultView`: `simple` | `verbose` (not built yet; the log starts simple)
  - `votes.defaultBallot`: `open` | `secret`

**Member** — campaignId, userId, baseRole (`gm` | `player`), activeActorId (set automatically to the player's first approved character; a pending or rejected character is never active), joined at. This is the only record of membership and roles. R1 enforces exactly one member with baseRole `gm` per campaign; multi-GM later means more than one. Anyone signed in can create a campaign; the campaign and its GM member row are created together, so the creator is its GM.

**Invite** — id, campaignId, email, code, invitedBy, status (`pending` | `accepted` | `revoked`; expired is worked out from `expiresAt`, not stored), expiresAt, acceptedBy. In R1 the GM copies an invite link or code and shares it; emailed invites may come later. The code alone is enough to join (email is an optional note for the GM); each code works once and expires after 14 days by default; joining is always as a player.

**Company** — id, campaignId, name. Its members are the characters whose company it is (an archived character keeps its company). A campaign has zero, one or many companies; each has its own charter, treasury (party ledger and places), titles and votes. A character belongs to at most one company at a time. From M4b's first step (ruled 2026-10-24) players found companies (founders recorded, with co-founder invitations accepted or declined) and ask to join, or a company invites a character; any member accepts until M8, when joining goes by vote and the charter decides; the GM can do any of it by fiat. **CompanyInvitation** — companyId, actorId, kind (`cofounder` | `invite` | `ask`), status (`open` | `accepted` | `declined` | `cancelled`), by, at. Company also keeps founders[] (actor ids).

**Title** (hat) — id, companyId, name, kind (`treasurer` | `archivist` | `custom`), description/notes, holderUserIds[]. Every company starts with a Treasurer and an Archivist; new titles and holders are chosen by vote (see `03`).

**FieldDefinition** — campaignId, appliesTo (actor kind), key (fixed when created, so renaming the label keeps values; one made by "Use this sheet layout" is the layout's key in lower case), fill (M4b, ruled 2026-10-25: the filled value it shows, copied from its sheet-layout field's `fill`; players read it, only the GM sets it), required (creation asks for it; copied from the sheet layout), label, type (`number`, `text`, `longtext`, `checkbox`, `list`, `ref` (later); fixed once created), choices (for `list`), group (shown to the GM as "Category"), order, showOnCard, hidden (hidden fields leave forms and cards, values are kept, the GM can show them again). A field no character has a value for can be deleted outright. Every field is optional. `number` holds whole numbers, negatives allowed. May come from a pack's sheet layout.

**Asset** — id, campaignId, kind (`portrait` | `sigil` | `handout` | `map`), name, storagePath, visibility (`gm` | `all` | `users`, with the user ids in `visibleTo`), revealedAt (for `map` | `handout`; a record of when it was shared — visibility alone decides who sees it), uploadedBy. Files live in Supabase Storage with matching access rules. Visibility lives only here: handouts and maps are Assets (the GM sets visibility and reveals them); portraits and sigils are visible to all campaign members. Players may add their own portraits; only the GM adds handouts, maps and sigils.

## Actors

**From the setting rules, for the sheet** (ruled 2026-10-25; the shapes are in 07):
- **traitLists** (a pack kind: backgrounds, affiliations, signs…) feed sheet fields of `type: "list"` with `from: "<traitList id>"` (kept on the campaign field as `from`, M5b step 0b); the value saved is the entry's id, shown by name; the owner picks or changes one any time (logged); without the list in the setting it's free text.
- **Sheet field types:** number, text, longtext, checkbox, list (choices, or `from` a trait list), ref (later).
- **saveModifiers** `[{id, name, value, appliesWhen}]`: each holds at times; never counted into a save's figure, shown with its number (05, "Save bonuses in the number"; ruled 2026-11-25).
- **skills** in the rules set `[{id, name, die, default, fill}]`, merged with classes' own `skills` (including `gmRolls`) into one Skills block.
- **movement.combat** (feet per round, for M6) alongside the exploration modes' movement.
- **encumbrance.labels** (what "At hand" is called), **encumbrance.slots** `{equipped, stowed, adjust}` and speed **bands**; **unencumbering** on items or categories (the Tiny section). Equipped, stowed and tiny are worked out from At hand, containers and that flag, never stored as a new state.
- **Options** carry `category` and `presets`; the rules set gives `optionCategories` (their order) and `optionPresets` (preset names).
- **spellcasting.reverseAt:** `memorise` | `cast` (default `cast`).
- **From M7** (07, Characters, XP and spells): `blurb` on entries, `creationGuide` and `creation.require` (guided creation), `spellcasting.recover` (when spells come back), abilities' `uses.per` (when uses come back), and the rules set's `xp` and `levelUp.when` settings; and (ruled 2026-10-29) the rules set's `abilities` names, classes' `race` (race-as-class), progression rows' `hpGain`, classes' `spellcasting.firstSpells`, `learnByLevel` and `scrollCopy`, and `combat.spellDisruption`. Read from the packs, never copied onto the character. A GM's label on an ability field wins over the pack's name wherever an ability is named (B6).

**Effect** (M5, ruled 2026-10-25) — campaignId, what it came from (a spell, an item, a potion, or "+ Effect"), targets (characters in M5; monsters and areas in M6), endsAt (on the campaign clock; none for concentration, "until broken" and permanent), caster (for concentration and "until broken"), hidden (the time left is the GM's: the pack's `durationHidden`, or "Hide time left"). ## Treasury, XP, charter

**Purse (first cut, December step 6; ruling pk-6, 2026-11-11; data built in piece a)** — table `purses`: id, campaignId, actorId (a character or a hireling) or locationId (the Party stash), exactly one; coins { coin key: whole number, never below zero }, keyed by the setting's coins (the rules set's `currency[].key`, 07; a coin that isn't there counts 0); version.
