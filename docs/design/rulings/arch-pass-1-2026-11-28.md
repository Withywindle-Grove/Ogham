## Candidate 1: one module for "Undo my last change"

**Verdict: yes, through the loop.** Intent: `docs/intents/2026-11-28-arch-undo-module.md`.

What the code shows (searched 28 Nov at `bf1c09c`): 29 files outside `src/core/undo.ts` call `latestChange`, 37 times. Each call finds the person's newest change of a kind, runs `undoChange`, picks the words and refreshes. `latestChange` answers null both when there is no such change and when the read failed, so a failed read shows "Nothing to undo."

| Id | Ruling | What it means | Francis |
|---|---|---|---|
| arch1-1 | **Build the module, through the loop** | One module in core does "undo my last change of this kind" and reports one of three endings: undone, nothing to undo, could not check. Each screen keeps its own words and its own refresh. One small spec, about three tickets. No stored data changes | "A" |
| arch1-2 | **The refactor keeps today's words** | A failed read still shows what each screen shows today, so no screen changes and the spec is "data and logic only". The module reports "could not check" to the screen all the same. The new words for that ending are one ⚑ for the next design sitting (`docs/10-open-questions.md`); one small ticket changes them after he rules | "A" |
| arch1-3 | **Candidate 1 does not wait for candidate 3** | The module makes its own small three-way answer for this one read. If candidate 3 is a yes, it takes that answer over and makes it general | "A" |
