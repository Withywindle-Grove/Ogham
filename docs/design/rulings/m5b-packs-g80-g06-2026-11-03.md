# Two pack gaps from the deathcaster-class conversion (design ruling, 2026-11-03)

The pack session converted a class supplement as **deathcaster-class** 0.1, a homebrew overlay on classic-advanced (one caster class, a long spell list; PR #308, G-80 and the G-06 update). Two things the pack carries can't work in the app today; Francis asked to prioritise both. Ruled one at a time, each with A — Builder, B — Critic and a synthesis. Ids `pg-1`, `pg-2`.

- **pg-1 · G-80: an option that sends a pack's spells to another class's list (A; M7).** A spell list may carry `extends: { listId, option, levelShift? }`. While the named option is on, every spell in this list also appears on the target list at its level plus `levelShift` (default 0). The class spell-list reader merges the extending lists; turning the option off removes them from the list, but spells a character already learned stay in their book, with a log line. One option may both hide the new class (as today) and extend the list. `pack:check` warns when `listId` matches no list in the attached packs. **Release M7**, with spell books and Learn a spell (about 2–3 builder turns); first spells at creation read the same list, so they pick it up then.
- **pg-2 · G-06's race side: an add-on's class reaching the base pack's races (A; M5b).** A class may carry `raceMaxLevels: { <raceId>: <level> | null }` (`null` = no limit). Wherever a race's class limits are read (creation's class offer, level-up's cap), every attached class's `raceMaxLevels` merges into that race's `classMaxLevels`. If the race already names the class, **the race wins** and `pack:check` warns of the clash; an unknown race id is a warning (another add-on may bring that race). A race not named stays closed to the class, as today. **Release M5b**, as a creation follow-up (about 2–3 builder turns). The rest of G-06 (an add-on patching another pack's rules set in general) stays the first release after R1.
