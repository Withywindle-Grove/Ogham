# Pack review, area 4 (fights and monsters): the questions pressed on (design ruling, 2026-11-04)

From the pack session's review of area 4 (`design/notes/area-4-fights-review-2026-11-04.md` §6, PR #397) and its gap rows G-127 … G-135. Ruled one at a time with Francis, each with A — Builder, B — Critic and a synthesis. Ids `fi-1` … . Rulings are added to this file as Francis gives them; items not yet ruled are listed under ⚑ at the end.

- **fi-1 (Francis, afternoon) Slow weapons (classic-advanced).** The book makes "slow weapons act last" a base rule, so it is **always on: no option.** The pack's `slow-weapons` option is removed (0.6.23; the rule sits in `initiative.notes`). **Crossbow reloading is the only option** here, default **off**. The options audit row reads "removed, fi-1".

- **fi-2 (A + warning) Shared monster ids (G-130).** Twenty-seven stat-block ids exist in both classic-advanced and fae-woodland; 115 fae-woodland encounter rows point at them, and "the pack on top wins" (eq-4) let the stack order pick the monster.
  - **Ruled:** the conversion pack **pins** them, as it does for the shared items (09, 2026-11-04): conv-fae-woodland-to-classic carries **fae-woodland's 27 monsters** restated in classic-advanced terms. The rule for which side is pinned: **the pin carries the setting being played** (items went the base setting's way because the rules base owns gear).
  - **And `pack:check` warns** when two packs in a stack share a stat-block id with different stats and no pack above both carries that id: "ghoul is in classic-advanced and fae-woodland with different stats; add it to a conversion pack or put the right one on top". Same check for item ids (eq-4's clash list already names them; this adds the "no pin" condition).
  - Encounter rows naming their pack (B) is not taken: a format change on every row that fixes encounter tables only, not Add foes or the GM reference.
  - With no conversion attached, eq-4 stands ("from X · also in Y").
  - **G-130 stays ◈** as the general question (M6's foe work may bring a cleaner format answer); this is the ruling for this stack.
  - Cost: the warning, ~1 turn (`plans/m5b-review-area-4.md`, build order 1). Pack session: the 27 pins in the conversion.

- **fi-3 (A) A kindred-class's knack counted twice.** bq3-5 applies: a pack fix, no `known` count at level 1 where the creation pick or roll gives the knack (fae-woodland). Whether rolls count toward `known` stays M7's question (G-119 open); if M7 rules the other way, the pack line is reversed, no app cost.

- **fi-4 (A) Classes with no quick-equipment kit** (the zine-compendium's own twenty; open since area 3). No kits are invented: the pack follows the book, and a GM who wants one adds it as campaign homebrew (`startingKits` with `classIds`). The Gear step's kit area gets a one-line **empty state** naming the class, "No quick kit for <class>: buy from the shop", so the player doesn't read an empty area as a fault; the same line serves a setting with no kits at all. App cost: one line and a test, with the creation follow-ups (`plans/m5b-0c-creation-survey.md`, PR 5). The question closes.

- **fi-5 (A, sequenced) `pack:check` for overlays and modifications.** A **shape-only** check now, as area-4 build order 2, built **after the gate's builds** (not before Thursday): the fields 07 lists for `overlays` and `modifications`, `meta.requires` present, every `links[].statBlockId` resolving in the required pack (or the files passed in stack order), reaction rows with a `result`; the unruled shapes of G-131, G-132 and G-133 are notes, not errors. The importer and the app's reading of the data stay M6-13. Why: the rebuilt monster-overlay (0.2.0) and its re-check need a check to run; both the checker and M6's reader follow 07, so the checker catches drift early. 1–2 turns, no app behaviour, no migration.

- **fi-6 (synthesis) Options that exist only in a newer edition** (classic-advanced; eleven, known from the options checklist's one-line summaries; the owner's books don't carry their full rules). One test per option: **is the checklist's line the whole rule, enactable with no guess?** Yes → kept, default off, `source` = "newer edition, checklist summary". No → dropped from the pack; its id and line go to the pack's private open-items, "returns when the books are owned". Death's door drops (the band between its two thresholds isn't given). Why: the pack standard is book × pack × app, and a switch the app can't honour without guessing is a trap at M6; dropping is reversible and cheap. The pack session judged the eleven (classic-advanced 0.6.24): **kept** `fighter-dominance`, `backstab-increase`, `blinded-attacks`, `magic-blade-light`; **dropped** `deaths-door` (and its `death.byOption` entry), `age-lifespan`, `advanced-hit-dice`, `high-level-play`, `xp-magic-items`, **Borderline, ruled kept** (Francis, 2026-11-04): `training` and `magic-armour-size`, whose lines leave one choice open, are read as "the GM picks" and kept with the four, their `note` naming the choice. Final: 6 kept, 5 dropped. Not taken: keep all, marked (A: ten switches the app can't honour); drop all (loses the complete ones for nothing).

- **fi-7 (synthesis) The overlay profile's fifth line, Morality** (Build, from the area-4 re-check #397, item 3). `profile { wants, appearance, voice, intelligence, morality?, other?: [{ label, text }] }`: `morality` is a named key (it's a line the GM reads for reactions and parley, like `wants`); `other` takes any further book line, shown after the named ones, so the next line needs no ruling. `pack:check` warns on an unknown profile key (area-4 build order 2). No app change until M6 reads profiles. Not taken: a key per book line (07 grows one ruling at a time); a free notes field only (the card can't order lines, the checker can't catch a typo'd key).

- **fi-8 (synthesis) A result that means "roll the region's table"** (G-136; fae-woodland's encounter-type table sends some rolls to "Regional"; table chaining by name found no such table and the GM tapped the region's table by hand). A table row may carry **`next: { regional: true }`** (extending ga-2's row `next`): the result opens the party's region's table (`wildEncounters.regionalTables`), or the list of regions when the region isn't known. `pack:check` treats a row with `next` as resolved and warns when `regional` is used in a rules set with no `regionalTables`. Not taken: a table-level `regionalResult: "Regional"` (a match on the result's text: one wording, one row); leaving it (a two-tap detour on a common roll). After the gate's builds, ~1 turn (area-2 plan, order 4's follow-up). Pack session: `next` on fae-woodland's Regional rows.
  - **fi-8b (synthesis, same day) A Regional cell in only some columns** (the type table is a column matrix; some rows go regional in two columns of four). A row's `next` may be keyed by column, as ga-2 keys it by terrain: **`next: { byColumn: { "<column>": { regional: true } | "<tableId>" }, default? }`**; the plain `regional: true` stays for all-Regional rows. `pack:check` warns on a `byColumn` key that isn't one of the table's columns. Not taken: a `columns: [...]` list limiting the flag (a one-off shape); the result text as marker; leaving mixed rows by hand.
